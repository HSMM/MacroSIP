# MacroSIP — development notes

MicroSIP-style SIP softphone for macOS 14+, universal (Apple Silicon and Intel). Swift 6, SwiftUI/AppKit,
SwiftPM only (no Xcode project), PJSIP 2.17 linked statically through the `CPJSUA` C target.
Built on an Apple Silicon Mac; the x86_64 half is cross-compiled (ADR 0012).

## Read first
- `docs/ROADMAP.md` — what goes into the first release, what comes next.
- `docs/GLOSSARY.md` — shared vocabulary. Use these terms in code and docs.
- `docs/adr/` — settled decisions. Do not reopen them silently; add a new ADR to change one.
- `docs/design/mockups.html` — approved UI mockups; `docs/design/SCREENS.md` — their text spec (elements, states, strings). UI code follows both.

## Layout
- `Sources/CPJSUA` — C shim and umbrella header over pjsua. The only place that includes PJSIP headers.
- `Sources/MacroSIPCore` — Swift engine: accounts, calls, presence, recording, storage. No UI imports.
- `Sources/MacroSIPApp` — SwiftUI/AppKit app.
- `Tests/` — Swift Testing (`import Testing`) for Core; XCTest is unavailable with Command Line Tools only.
- `scripts/` — `build-pjsip.sh`, `make-app.sh`, `make-dmg.sh`, `make-appcast.sh`, `publish-appcast.sh`, `make-icon.swift`, `update-cask.sh`, `test.sh`, `selftest-call.sh`, `check-strings.sh`. `third_party/` holds the PJSIP, OpenSSL and Opus builds (git-ignored except `pjsip/config_site.h`; layout in `scripts/README-build.md`).

## Rules
- One product, one build: `MacroSIP`, bundle id `com.hsmm.macrosip` (ADR 0003). No build flags for features.
- PJSIP callbacks arrive on PJSIP worker threads. Hop to the main actor before touching app state; never block a PJSIP thread on the main actor.
- Every `pjsua_*` call that can fail returns `pj_status_t`; check it and surface the error text via `pj_strerror`.
- Passwords live only in Keychain. Everything else is JSON in `~/Library/Application Support/MacroSIP/`.
- Strings: see "Localization" below. English is the base; Russian is maintained alongside; a new string is not done until both languages have it.
- Run tests with `scripts/test.sh`, never bare `swift test` (it cannot find the Testing macro plugin under Command Line Tools). A milestone is done only after: `swift build` clean, tests green, `scripts/selftest-call.sh` passes, and a real call verified (pjsua CLI as the second phone, or the owner's SIP account).
- Commit after each working milestone and push to `main`.
- SwiftUI `@State` does not compile under Command Line Tools (its macro plugin ships only with Xcode). Use the `@Local` wrapper from `Sources/MacroSIPApp/Views/Components/Local.swift`; it is a drop-in for `@State`.
- Opus and OpenSSL are built from pinned sources by `scripts/build-pjsip.sh` and linked as universal static archives from `third_party/deps/universal/lib` (Package.swift), so the .app has no dylib dependencies outside the system; never switch them to `.linkedLibrary` or to Homebrew. No Homebrew packages are needed to build.
- **Codecs built**: Opus, G.722, G.711 and, from pjproject's own `third_party` sources, G.722.1 (Siren7/14), GSM, iLBC and Speex (`config_site.h` `PJMEDIA_HAS_*_CODEC`; `build-pjsip.sh` no longer passes `--disable-{g7221,gsm,ilbc,speex}-codec` and stops if configure disables one or a library is missing). Their archives (`libg7221codec.a`, `libgsmcodec.a`, `libilbccodec.a`, `libspeex.a`) are in `pjsipLibraries` in `Package.swift`; keep that list in sync with `third_party/pjsip/LINKFLAGS` after changing codecs. No G.729. Changing `config_site.h` rebuilds PJSIP for both architectures (about 2-5 min; OpenSSL and Opus stay cached). Codec ids and defaults: docs/ENGINE.md "Codecs".
- **Universal build**: `build-pjsip.sh` builds every library for arm64 and x86_64 (deployment target 14.0) and merges them with `lipo`; `make-app.sh release` (and so `make-dmg.sh`) runs `swift build --arch arm64 --arch x86_64` and checks both slices; `make-app.sh debug` and plain `swift build` stay native. `ARCHS=arm64 scripts/make-app.sh` builds a single-arch release. Test the Intel slice on Apple Silicon with `SELFTEST_ARCH=x86_64 scripts/selftest-call.sh` (needs Rosetta 2: `softwareupdate --install-rosetta --agree-to-license`).
- Debug builds (`scripts/make-app.sh debug`; a release app ignores the demo options and starts the real app on the real data, Keychain prompt included) accept `--mock-engine`, `--demo-state <name>`, `--data-dir <path>`, `--snapshot <prefix>` (the app quits once the PNGs are written; a state with a ringing call or an open sheet needs `timeout`), `--appearance light|dark` (forces the theme, for screenshots); all builds accept `--log-level 0-6` (or `MACROSIP_LOG_LEVEL`) for PJSIP verbosity; see `Sources/MacroSIPApp/Model/LaunchOptions.swift`. Demo launches use a temp data dir and never touch the real Keychain.
- Do not add dependencies without an ADR.
- Versions are `YY.MINOR.PATCH` (ADR 0010): the first release is `26.0.0`; tags carry the bare number. `make-app.sh` takes the version from `git describe`.

## Localization
- All UI text goes through `L` in `Sources/MacroSIPApp/Model/Strings.swift`; views never contain user-visible literals. `L.loc(key, "English default")` calls `String(localized:defaultValue:bundle: .module)`.
- Classic `Localizable.strings` / `.stringsdict`, not `.xcstrings`: `xcstringstool` ships only with Xcode, so SwiftPM under Command Line Tools cannot compile catalogs (ADR 0011). `Package.swift` has `defaultLocalization: "en"` and `resources: [.process("Resources")]` on `MacroSIPApp`; the build produces `MacroSIP_MacroSIPApp.bundle`, which `make-app.sh` copies to `Contents/Resources` (where `Bundle.module` finds it).
- **Add a string**: (1) add `static var`/`func` in `L` with a dotted key and an English default (interpolations become `%@` for text and `%lld` for integers; with two or more arguments use `%1$@`, `%2$@` in both files); (2) add the key to `Resources/<lang>.lproj/Localizable.strings` for every language in `scripts/check-strings.sh`; (3) run `scripts/check-strings.sh` (keys in `L` equal keys in every language, placeholders match, plural categories complete).
- **Counts** (contacts, calls, entries, participants) use `Localizable.stringsdict` in every language instead: key with `NSStringLocalizedFormatKey` `%#@count@`, categories `one`/`other` for English, `one`/`few`/`many`/`other` for Russian. Do not add the same key to `.strings`.
- Not translated on purpose: product, codec and protocol names (SIP, SRTP, TLS, STUN, ICE, DTMF, REGISTER), the diagnostics report and log lines. The microphone prompt is in `packaging/InfoPlist/<lang>.lproj/InfoPlist.strings`, copied by `make-app.sh`.
- Quality, volume and device-follow states for snapshots: `--demo-state quality-good|quality-fair|quality-poor|quality-poor-calls|call-volume|headset|headset-back` (the mock cycles good 8 s, fair 8 s, poor 14 s unless a state pins the level; `MockEngine.simulateHeadset(connected:)` plugs "AirPods Pro" in and out). `call-volume` also writes `<prefix>-popover.png`, because a popover is a window of its own.

Keys live in `AppSettings.quickKeys` (settings.json); BLF subscriptions are kept by `AppModel+QuickKeys.swift` (observes the keys, the accounts and the presence map). The engine reports `PresenceStatus.ringing` (Asterisk "Ringing" note) with the note in `.buddyPresence(contactURI:, status, note:)`: `AppModel.handleQuickKeyPresence` lights every key whose URI matches (orange, blinking, click dials the pickup code) and clears it on any other status; the tooltip shows "Ringing · N min" once the line has rung a minute. dnd is shown as "on the phone" (red), away as available; `AppModel.setQuickKeyRinging(_:for:)` stays as the seam for demo states. - Contact card (screen 12): `--demo-state contacts|contact-card|contact-card-new`. The demo address book (`DemoState.demoContacts()`) has several numbers per person, two generated photos, two favourites and an organization-only contact; `contact-card` opens the card for the first favourite and the snapshot writes `<prefix>-card.png` next to `-main.png`. Contacts live in `contacts.json` as `firstName`/`lastName`/`numbers` (plus `name`/`number` for downgrades; photos are `photos/<id>.jpg`, `ContactStore` hands them back in `Contact.photo`); older files with only `name`/`number` are read as well (name split at the last space, number as Other, default).

- Hold music, sound events, audio test, notice tone, voicemail and Google sign-in: `--demo-state settings-audio|settings-recording|voicemail` (`settings-audio` and `settings-recording` are generic `settings-<tab>` states; `voicemail` lets the mock report two new messages on Office with `MockEngine.simulateVoicemail(account:new:old:)`, so the status bar shows the envelope badge and `<prefix>-menu.txt` the "Voicemail: 2 new" item). `--demo-state selftest` checks all of them (`DemoState.soundChecks`) through the mock's records (`holdMusic`, `recordingNotice`, `playedSounds`, `testTones`, `voicemailState(for:)`).
  - **Hold music** (`AppSettings.audio.holdMusic`, Settings › Audio › Hold music: Built-in / Custom file… / Off): `AppModel.applyHoldMusic` hands it to `engine.setHoldMusic` at start and on every change (`updateSettings`); a file the engine cannot read leaves the engine's source alone and shows the reason in the group footer (`AppModel.holdMusicError`) and a banner.

## Polish and release (milestone 6)
- **Log file**: `~/Library/Logs/MacroSIP/MacroSIP.log` (`Platform/AppLog.swift`). Engine `.log` events go to categories `engine` (messages prefixed "engine: ") and `pjsip`; app code uses `AppLog.app/.recording/.presence` (os_log plus file). Each line is one `write(2)` on an `O_APPEND` descriptor, so a crash loses nothing. Rotation at 2 MB, three files: `MacroSIP.log`, `.1.log`, `.2.log`. Line: `date [category] E|W|I|D text`. `--log-level` still sets PJSIP verbosity only. Demo launches write no file; `MACROSIP_LOG_DIR=<dir>` redirects it (also for demos). New app-side logging uses `AppLog`, not a bare `Logger`.
- **Diagnostics**: Settings › General › Advanced › Troubleshooting. "Copy Diagnostics" puts versions, macOS, accounts (no passwords) and settings on the clipboard; "Open Log Folder" reveals the log in Finder.
- **Launch at login**: `SMAppService.mainApp` (`AppModel.applyLaunchAtLogin`). The toggle shows the real state when the pane opens and at start, shows macOS's error under the row if it refuses, and offers "Open Login Items…" when the status is `requiresApproval`. Limitation: it only works from a bundled app (`dist/MacroSIP.app` or `/Applications`), never from `swift run` or demo launches, and an ad-hoc signed app may need approval in System Settings › General › Login Items; if macOS reports the app as not found after it was moved, toggle off and on once from the new location.
- **Language**: Settings › General (System / English / Русский) writes `AppleLanguages` in the app's defaults (nil removes it) and offers a restart; after the restart `Bundle.module` and the system menus use that language.
- **About**: standard panel (`AboutPanel` in `Platform/AppInfo.swift`), reached from MacroSIP › About MacroSIP. Version is `Product.version`, build is `CFBundleVersion`; the copyright and credits are fixed strings.
- **App icon**: `swift scripts/make-icon.swift` draws the icon (source of truth: `packaging/AppIcon.svg`, a dial pad whose pressed keys trace an M on a green gradient) into `packaging/AppIcon.icns` and `AppIcon-1024.png`; run `swift scripts/make-icon.swift` after changing the artwork.
- **DMG**: `scripts/make-dmg.sh [release]` builds the app and writes `dist/MacroSIP-<version>.dmg` (universal; volume "MacroSIP", Applications symlink, ad-hoc signed, no notarization).
- **Updates** (ADR 0013): Sparkle 2.7.3 (SwiftPM binary XCFramework, pinned exactly). `Platform/Updater.swift` wraps `SPUStandardUpdaterController`; it starts in `applicationDidFinishLaunching` except for `--mock-engine`, demo launches and a binary outside an .app (`swift run`), where Settings › General › Updates is disabled with a note. `make-app.sh` copies `Sparkle.framework` into `Contents/Frameworks`, signs its XPC services, `Autoupdate`, `Updater.app` and the framework before the app, and writes `SUFeedURL` (`https://raw.githubusercontent.com/HSMM/MacroSIP/gh-pages/appcast.xml`), `SUPublicEDKey`, `SUEnableAutomaticChecks` and `SUScheduledCheckInterval` (24 h) into Info.plist. Release candidates are appcast items on the `beta` channel; the "Include release candidates" toggle (UserDefaults `updates.includeReleaseCandidates`) decides `allowedChannels`. Sparkle's tools (`generate_keys`, `generate_appcast`, `sign_update`) are in `.build/artifacts/sparkle/Sparkle/bin` after `swift build`.
- **CI**: `.github/workflows/ci.yml` (push and PR to main). Job `build` on `macos-15` (arm64): `build-pjsip.sh` with `third_party/pjsip` and `third_party/deps` cached (key: hash of the script and `config_site.h`), build, tests, selftest natively and the x86_64 slice under Rosetta 2, universal release app as artifact. Job `intel` on `macos-15-intel` (x86_64) takes the universal libraries and the app from `build`, launches the app for 15 s, and runs `swift build`, `scripts/test.sh` and `scripts/selftest-call.sh` natively. `release.yml` runs on tags `[0-9]*.[0-9]*.[0-9]*` and builds the same universal DMG on arm64 (with the Rosetta selftest).

- **Headset buttons** (USB/HID call control): `Platform/HeadsetButtons.swift` watches HID devices through `IOHIDManager` (`import IOKit.hid`): top-level collections on the Telephony page (0x0B: Headset 0x05, Telephony 0x01, Handset 0x04) and Consumer Control devices (0x0C/0x01) that carry Telephony elements (a keyboard's media keys and the 3.5 mm jack's "Headset" have none and are ignored). The manager only enumerates; each telephony device is opened on its own (`IOHIDDeviceOpen`), so no keyboard-class device is touched. A Telephony-page collection opens without a prompt; a device that exposes its telephony controls only inside a Consumer Control collection may be refused by macOS (Input Monitoring): the failure is logged (`headset buttons: cannot open ...`) and the device ignored. That case has not been tested on real hardware. Input usages: Hook Switch 0x0B/0x20, Flash 0x21, Hold 0x23, Redial 0x24, Drop 0x26, Phone Mute 0x2F; `HeadsetReportDecoder` (pure, no IOKit) turns them into `HeadsetEvent`s. The hook switch comes as a level (1 off-hook, 0 on-hook; "no preferred state" in the descriptor) or as a momentary button ("preferred state"); a switch that releases within 300 ms is treated as a button from then on, and so is one whose release arrives within 1 s of the call its off-hook answered (`HeadsetButtons.callAnswered` from `AppModel+Headset.swift`), so a long first press cannot answer and hang up in one go. `AppModel+Headset.swift` maps them: off-hook or a hook press answers the ringing call (the active one goes on hold), on-hook ends the active call, a hook press with no call ringing hangs up the current one, Flash answers the waiting call or swaps the held one in, Phone Mute toggles the current call's microphone, Redial calls the last outgoing number when no call exists. The LEDs Off-Hook (0x08/0x17), Ring (0x08/0x18) and Mute (0x08/0x09) are written as output reports when the device has them, from `afterCallsChanged` (`syncHeadsetIndicators`), so the headset follows the call state and level-type devices reset their hook after a remote hang-up. IOKit callbacks run on the controller's private queue; events and the device name hop to the main actor. `AppModel.headsetButtonsEnabled` (default on, `setHeadsetButtonsEnabled(_:)` starts and stops the controller) and `headsetButtonsDevice` (name of the connected device, nil when none, for the UI) are the API for Settings. Hot-plug is logged (`headset buttons: <name> connected, hook button|switch, controls ...`, `... disconnected`) in the `app` category. Demo launches never open IOKit; `HeadsetButtons.simulate(_:)` (DEBUG) injects events and `--demo-state selftest` checks the decoder, answer/hang-up/mute/redial and the LED state through it. Out of scope: Bluetooth headsets whose buttons speak HFP (AT commands) rather than HID; macOS handles those itself and they do not appear as HID telephony devices.

## Releasing
1. Everything green locally: `swift build`, `scripts/test.sh`, `scripts/selftest-call.sh`, `scripts/make-dmg.sh`; mount the DMG and start the app.
2. The version comes from the tag: `make-app.sh` writes the nearest tag into `CFBundleShortVersionString`, `Product.version` reads it at run time (About panel, SIP `User-Agent`), and the release job fails if the app's version and the tag differ. `Product.fallbackVersion` (used by tools without a bundle) is bumped to each final release. Update `docs/ROADMAP.md`. Tag every release on a later commit than the previous one, a final release after its candidate too: Sparkle orders updates by `CFBundleVersion`, the commit count, and `make-appcast.sh` refuses a build number the feed already has.
3. Tag and push: `git tag 26.0.0 && git push origin 26.0.0`. A release candidate is tagged `26.0.0-rc.1`; any tag with a `-` becomes a GitHub pre-release. Homebrew accepts such versions, so the cask for a candidate has `version "26.0.0-rc.1"` and installs `MacroSIP-26.0.0-rc.1.dmg`.
4. `release.yml` (only in `HSMM/MacroSIP`) refuses a tag other than `N.N.N` or `N.N.N-rc.N` and a missing `SPARKLE_PRIVATE_KEY`, builds `dist/MacroSIP-<tag>.dmg`, checks the build number against the published appcast (`scripts/publish-appcast.sh --check`), creates the GitHub Release with generated notes (after a fixed line saying macOS asks for the microphone again after an update), then adds the release to the update feed with `scripts/publish-appcast.sh <tag> <dmg>`: it fetches `gh-pages` with the checkout's credentials (creates the branch on the first run), renders the release body to HTML (GitHub's Markdown API), runs `scripts/make-appcast.sh <tag> <dmg> dist` (Sparkle's `generate_appcast`: EdDSA signature with the `SPARKLE_PRIVATE_KEY` secret, download URL of the release asset, `beta` channel for tags with a suffix, every earlier item kept), commits `appcast.xml` to `gh-pages` (retrying after a fresh fetch if another release pushed first) and attaches it to the release. The appcast keeps the notes as they were at release time; to change them, edit the release and re-run the job. Then it runs `scripts/update-cask.sh <tag> <dmg>` against a clone of `HSMM/homebrew-tap` (needs the `TAP_TOKEN` secret, see README "Releasing") which commits `macrosip <tag>` to `Casks/macrosip.rb`. By hand: `scripts/update-cask.sh <version> dist/MacroSIP-<version>.dmg` writes `dist/macrosip.rb` and prints the git commands; with `TAP_DIR=<clone>` it commits and pushes.
5. Check: `brew tap hsmm/tap && brew install --cask hsmm/tap/macrosip`, then launch (right-click › Open the first time). Check the feed: `curl -s https://raw.githubusercontent.com/HSMM/MacroSIP/gh-pages/appcast.xml` lists the new item; an installed older version finds it with MacroSIP › Check for Updates… (a candidate only with "Include release candidates" on).
6. The cask template is `packaging/homebrew/macrosip.rb` (checked with `brew style --cask` inside a tap; keep `desc` free of the platform name and `depends_on` stanzas in that order).
7. Update signing key (EdDSA): the public half is `SPARKLE_PUBLIC_KEY` in `make-app.sh`; the private half is the Actions secret `SPARKLE_PRIVATE_KEY` and, on the owner's Mac, the login keychain items "MacroSIP Sparkle private key" (`security find-generic-password -s "MacroSIP Sparkle private key" -w`) and Sparkle's own (account `macrosip`). Never commit it. To restore the secret: `security find-generic-password -s "MacroSIP Sparkle private key" -w | gh secret set SPARKLE_PRIVATE_KEY --repo HSMM/MacroSIP`. By hand (no CI): `SPARKLE_PRIVATE_KEY=... APPCAST_IN=<current appcast.xml> scripts/make-appcast.sh <version> dist/MacroSIP-<version>.dmg dist`, then upload `dist/appcast.xml` to the release and to `gh-pages`.
8. Not covered: Developer ID signing and notarization (v2 candidates). Ad hoc builds keep the hardened runtime and carry `com.apple.security.cs.disable-library-validation` in `packaging/Entitlements.plist`, because library validation would refuse the embedded Sparkle framework (no Team ID); with a Developer ID, remove that entitlement (ADR 0013). `make-app.sh` leaves only `/usr/lib/swift` and `@executable_path/../Frameworks` as rpaths and fails if the binary needs another `@rpath` library.
