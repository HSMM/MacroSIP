Troubleshooting

The first launch is blocked

"MacroSIP cannot be opened because the developer cannot be verified": the app is signed ad hoc, not notarized. Right-click MacroSIP in Applications and choose Open, or run xattr -dr com.apple.quarantine /Applications/MacroSIP.app once. Details in Installation. Updates installed by the app itself open without this dialog.

Nobody hears me: microphone permission

The call panel shows "Microphone access is off" with Open System Settings. Allow MacroSIP under System Settings › Privacy & Security › Microphone. Because of the ad hoc signature macOS asks again after every update; allow it once more on the first call after updating. Then check the level meter in Settings › Audio while speaking.

The account shows "403" or "401"

Status Meaning What to do
401 Unauthorized, 403 Forbidden The server rejected the credentials. Settings › Accounts shows "REGISTER rejected at 14:52. Check the username and password." Check Username, Password and, if your PBX uses a separate authentication name, Auth username in the Advanced group. Press Test in the editor: "Registered successfully (120 ms)" confirms the fix.
"No response" (Test) or "Office · retry in 8 s" No answer from the server. Check the server name and port, the Transport (UDP, TCP or TLS; the PBX must listen on the one you chose) and firewalls. The engine retries with backoff.
"Registering…" that never ends Packets leave but no answer comes back. Same as above; try another transport, or set a STUN server.

See Accounts for every status.

TLS certificate errors

With Transport: TLS the engine verifies the server certificate against the system root certificates. A certificate that does not match the host, is expired or is self-signed fails the registration permanently (no retry) with a TLS reason in the status and the log. Fix the certificate on the server, or, for a self-signed one you trust, turn off Verify server certificate in the Advanced group of the editor ("Turn off only for a server with a self-signed certificate.").

No audio or one-way audio

Usually NAT or a firewall between you and the PBX. Set a STUN server, keep Use ICE and Use rport on, allow UDP on the local SIP port and the RTP port range, and check the devices in Settings › Audio. The full checklist is in Audio.

Calls drop when the network changes

The engine re-registers at once on a network change or wake and sends a re-INVITE so calls survive an IP change; the call panel shows "Reconnecting… 12 s" meanwhile and the status bar "Office · retry in 8 s". If the media does not return within 60 s the call ends with "Connection lost" in the call log. If drops persist, lower Keep-alive interval in Settings › Network.

Headset buttons do nothing

MacroSIP reads the HID telephony controls of USB headsets (hook, flash, hold, mute, redial). Check that Headset buttons in Settings › Audio is on and that the row names your device ("Connected: Jabra Evolve2 65"); "No headset with call controls" means no connected device exposes telephony controls. The log file has the line "headset buttons: connected, …" when a device is picked up, and "headset buttons: cannot open …" when macOS refused to open it; that can be a matter of the Input Monitoring permission (System Settings › Privacy & Security). Bluetooth headsets whose buttons work through the hands-free profile are handled by macOS and are not supported. The headset auto-switch in the same pane is a separate feature and does not need the buttons.

The caller hears no hold music

Check Source in Settings › Audio › Hold music: Off sends silence. Many PBXs replace what a phone sends on hold with their own music, so the caller hears the server's music instead of MacroSIP's; that is a server setting. A file the engine could not read keeps the previous source and the group footer names the reason ("The file could not be used: …"). You never hear the hold music yourself.

Caller names are wrong or missing

The name comes from the SIP display name, then from a contact matching any of its numbers, then from a directory source asked for at most one second. Add the number to a contact, or add a directory source (Directory).

Directory and LDAP errors

Text Meaning
"Cannot connect to ldap.example.com" Host unreachable or wrong port;
"Timed out" No answer in 3 s (30 s for an import).
"Invalid bind DN or password" The simple bind was refused. Leave Bind DN empty for anonymous search.
"The server must be ldap://host or ldaps://host" The Server field has no scheme.
"Enter an http, https or file URL", "HTTP 404" URL source unreachable or wrong.
"No number column in the header", "The file is not text" CSV without a recognised number column, or not a text file.
"The file is not valid JSON", "No array of contacts in the JSON" JSON source malformed.
"Access denied", "Contacts access has not been requested" macOS Contacts permission; allow MacroSIP in System Settings › Privacy & Security › Contacts.
"Sign in required" Google Contacts without a valid token (not signed in yet, or access revoked). Select the source in Settings › Directory and press Sign In…; the browser opens Google's consent page.
"Google sign-in is not configured in this build" The build has no Google client id, so Google Contacts cannot be signed in; the other source types work. Install a build that is configured for Google sign-in.

A library message that MacroSIP cannot translate (an LDAP diagnostic) is shown as it is. A failed source is skipped for 60 s and then retried.

The log file and Copy Diagnostics

MacroSIP writes ~/Library/Logs/MacroSIP/MacroSIP.log (2 MB per file, 3 files kept). Settings › General › Advanced › Open Log Folder reveals it in Finder; Copy Diagnostics copies versions, macOS, accounts without passwords and settings to the clipboard ("Diagnostics copied to the clipboard."). For a deeper SIP trace start the app with open /Applications/MacroSIP.app --args --log-level 5 (0–6). The app also logs to the unified log under the subsystem com.hsmm.macrosip.

Where settings and contacts are stored

What Where
Accounts (without passwords), contacts, call log, settings, quick keys ~/Library/Application Support/MacroSIP/ as accounts.json, contacts.json, calllog.json, settings.json; photos in photos/. Written atomically; a damaged file is set aside as <name>.broken-<date>.json or contacts.damaged-<date>.json and the app starts with what it could read.
Passwords (SIP accounts, LDAP bind) Login Keychain, service com.hsmm.macrosip, one item per account id. Deleting an account removes its item.
Recordings ~/Music/MacroSIP Recordings or the folder chosen in Settings › Recording.
Log ~/Library/Logs/MacroSIP/.

To move to another Mac copy the Application Support folder and re-enter the passwords.

Reporting an issue

Open an issue at github.com/HSMM/MacroSIP/issues with:

  1. The MacroSIP version (MacroSIP › About) and macOS version.
  2. The output of Copy Diagnostics (it contains no passwords).
  3. What you did, what you expected, what happened, and the time, so the matching lines in MacroSIP.log can be found. Attach the log for call or registration failures, with anything private removed.
  4. The PBX or provider type (Asterisk, FreePBX, 3CX, …) if you know it.

Feature requests go to the same place; the plan is in the roadmap.
